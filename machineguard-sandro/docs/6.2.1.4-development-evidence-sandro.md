##### Sandro Dinklange — Testing BDD e integración continua

En este Sprint se configuró la automatización de pruebas de los dos Web Services del alcance. En `machineguard-core-api` se incorporó Cucumber al build de Maven y en `machineguard-edge-api` se incorporó pytest-bdd, de modo que los Acceptance Tests de las historias del Sprint 1 se ejecutan junto con las pruebas unitarias y de integración existentes con un solo comando (`mvn test` y `python -m pytest`, respectivamente).

Además, se agregó a cada repositorio un workflow de GitHub Actions (`.github/workflows/ci.yml`) que ejecuta toda la batería en cada push a las ramas `main`, `develop`, `feature/**`, `release/**` y `hotfix/**`, y en cada pull request hacia `develop` y `main`. El workflow publica los reportes de cada ejecución como artefactos descargables. De esta forma, un cambio que rompa un criterio de aceptación ya verificado se detecta antes de integrarse a `develop`.

| Repositorio | Workflow | Entorno | Comando de pruebas | Artefactos |
|---|---|---|---|---|
| machineguard-core-api | `CI` (`.github/workflows/ci.yml`) | Ubuntu, Temurin JDK 21, caché de Maven | `mvn -B verify` | `cucumber-report`, `surefire-reports` |
| machineguard-edge-api | `CI` (`.github/workflows/ci.yml`) | Ubuntu, Python 3.12, caché de pip | `python -m pytest -v --junitxml=reports/junit.xml --cucumberjson=reports/cucumber.json` | `test-reports` |

Los README de ambos repositorios se actualizaron con las instrucciones para ejecutar la suite BDD y ubicar sus reportes. Los commits de los archivos `.feature` y Steps se detallan en 6.2.1.5.
