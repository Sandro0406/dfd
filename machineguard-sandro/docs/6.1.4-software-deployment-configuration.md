**Web Application**

La Web Application es una Single Page Application en Angular 18.2 que se publica en GitHub Pages desde el repositorio `MachineGuard/machineguard-web` mediante el workflow `.github/workflows/deploy-pages.yml`, que se ejecuta con cada `push` a `main` y de forma manual (`workflow_dispatch`).

| Elemento | Configuración |
|---|---|
| Hosting | GitHub Pages, publicado por el workflow de GitHub Actions |
| Disparador | `push` a `main` o ejecución manual |
| Build | Node.js 22 con caché de npm, `npm ci` y `npm run build -- --base-href=/machineguard-web/` |
| Artefacto | Carpeta `dist/machineguard-web/browser` |
| Jobs | `build` (compilación y artefacto de Pages) y `deploy` (publicación en el entorno `github-pages`) |
| URL publicada | https://machineguard.github.io/machineguard-web/ |
| Configuración de ejecución | `src/environments/environment.production.ts` (`apiBaseUrl`); en desarrollo, `proxy.conf.json` redirige `/api` a `http://localhost:8080` |

Pasos para el despliegue:

1. En el repositorio, ingresar a **Settings > Pages** y seleccionar **GitHub Actions** como fuente de publicación.
2. Integrar los cambios a `main` mediante un pull request desde `develop`, o ejecutar el workflow manualmente.
3. Verificar en la pestaña Actions que los jobs `build` y `deploy` finalicen correctamente y abrir la URL publicada.
4. Una vez desplegada la RESTful API, reemplazar `apiBaseUrl` en `environment.production.ts` por su URL pública y volver a publicar.

> Pendiente (Camilla y Pedro): (1) `apiBaseUrl` apunta hoy a `/api/v1`, que en GitHub Pages no corresponde a ninguna API; (2) la RESTful API debe permitir CORS para el origen `https://machineguard.github.io`, ya que hoy no tiene configuración CORS; (3) al recargar una ruta interna, como `/machineguard-web/dashboard`, GitHub Pages responde 404; se resuelve copiando `index.html` como `404.html` después del build.

**RESTful API central**

La RESTful API (`MachineGuard/machineguard-core-api`) se empaqueta con el `Dockerfile` del repositorio en dos etapas:

1. **Build:** imagen `maven:3.9.9-eclipse-temurin-21`, que ejecuta `mvn -B -DskipTests package`. Las pruebas se omiten en esta etapa porque ya se ejecutan en el workflow de CI antes de integrar cada cambio.
2. **Runtime:** imagen `eclipse-temurin:21-jre` con el JAR de la aplicación, expuesto en el puerto 8080. Al iniciar, Flyway aplica las migraciones pendientes sobre PostgreSQL.

| Variable de entorno | Descripción | Valor por defecto |
|---|---|---|
| `DB_URL` | URL JDBC de PostgreSQL | `jdbc:postgresql://localhost:5432/machineguard` |
| `DB_USERNAME` | Usuario de la base de datos | `machineguard` |
| `DB_PASSWORD` | Contraseña de la base de datos | (obligatoria) |
| `IAM_JWT_SECRET` | Clave de firma HMAC-SHA256 de los JWT, de al menos 32 bytes | (obligatoria) |
| `IAM_ACCESS_TOKEN_TTL_SECONDS` | Duración del access token, entre 60 y 3600 segundos | `900` |
| `IAM_REFRESH_TOKEN_TTL_DAYS` | Duración del refresh token | `30` |
| `IAM_BOOTSTRAP_ENABLED` y `IAM_BOOTSTRAP_*` | Creación única de la organización y el administrador inicial | `false` |
| `TRACEABILITY_RETENTION_MONTHS` | Meses de retención de excursiones cerradas | `60` |
| `TRACEABILITY_PURGE_ENABLED` | Activa la depuración diaria por retención | `false` |
| `TRACEABILITY_MEASUREMENTS_TABLE` | Tabla de mediciones que consulta Traceability | `measurements` |

Despliegue local con Docker Compose:

1. Instalar Docker Desktop con Docker Compose v2.
2. Copiar `.env.example` a `.env` y reemplazar `MACHINEGUARD_DB_PASSWORD` e `IAM_JWT_SECRET`.
3. Ejecutar `docker compose up --build`. Compose levanta `postgres:16-alpine`, espera a que esté saludable y luego inicia la API.
4. Verificar la documentación en `http://localhost:8080/swagger-ui.html` y `http://localhost:8080/v3/api-docs`.

Despliegue en la nube:

1. Crear una instancia administrada de PostgreSQL 16 y obtener su URL de conexión.
2. Crear un servicio web conectado al repositorio `machineguard-core-api` (rama `main`) que construya la imagen con el `Dockerfile`.
3. Registrar las variables de entorno de la tabla anterior. `IAM_JWT_SECRET` y `DB_PASSWORD` se guardan como secretos de la plataforma y nunca en el repositorio.
4. Activar el bootstrap una sola vez para crear el administrador inicial y luego desactivarlo.
5. Verificar `https://<url-de-la-api>/swagger-ui.html` y registrar la URL pública en la Web Application y en la Edge API.

**Edge API**

La Edge API (`MachineGuard/machineguard-edge-api`, con Flask, Peewee y SQLite) se instala en el Edge Gateway del cliente (Raspberry Pi o equivalente), que recibe las lecturas de los nodos ESP32 por la red local y las publica en la RESTful API.

1. Instalar Python 3.12 o superior.
2. Clonar el repositorio desde la rama `main`.
3. Crear el entorno virtual con `python -m venv .venv`, activarlo e instalar las dependencias con `pip install -r requirements.txt`.
4. Configurar las variables de entorno.
5. Ejecutar `python run.py`. El servicio queda disponible en el puerto 5000 de la red local y se verifica con `GET /api/v1/edge/health`.

| Variable de entorno | Descripción | Valor por defecto |
|---|---|---|
| `MACHINEGUARD_API_URL` | URL base de la RESTful API; vacía significa sin conectividad | vacía |
| `EDGE_DEVICE_CREDENTIAL` | Credencial del gateway, enviada en la cabecera `X-Device-Credential` | vacía |
| `EDGE_GATEWAY_ID` | Identificador del gateway | `gateway-001` |
| `EDGE_DATABASE_PATH` | Archivo SQLite del Local Buffer | `edge.db` |
| `EDGE_BUFFER_CAPACITY` | Capacidad máxima del Local Buffer | `10000` |
| `EDGE_SYNC_BATCH_SIZE` | Lecturas por lote al sincronizar | `100` |
| `EDGE_SAMPLING_INTERVAL` | Sampling Interval por defecto, en segundos | `60` |
| `EDGE_AVAILABILITY_CHECK_SECONDS` | Frecuencia de revisión de nodos Offline | `30` |
